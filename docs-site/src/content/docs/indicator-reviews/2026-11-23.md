from two things already public: an OpenSourceMalware post of 2026-10-30 that
the last three reviews did not record, and the hijacked releases that earlier
reviews found and could only write down as comments, because the list for them
did not exist until 3.2.0. One of the additions closes a real miss: two loader
variants that sat in GitHub repositories this year reached review only, not
confirmed. See Notes.

## Upstream state

The dossier has not moved since July. No vendor published new analysis of the
campaign between 2026-11-16 and 2026-11-23. The loader's strings have not
rotated in anything read this week.

What the 2026-10-30 post adds is history, and it changes what this set should
match:

- **The payload is older than the campaign's first documented victims.** On
  2025-05-04, in 90 minutes, nine releases went out from one maintainer's npm
  account. Each has one line appended to `index.js` or `webpack.config.js`
  after 253 or 1,012 whitespace characters, opening
  `global['_V']='5-itsa';global['r']=require;`. The chain behind it uses BNB
  Smart Chain and Ethereum transaction data, one XOR key this set already
  carries (`ThZG+0jfXE6VAGOJ`) and one server it already carries
  (`154.91.0.103`).
- **Three releases are still on npm.** `itsa-jsext@2.0.3`,
  `itsa-react-docviewer@16.1.2` and `itsa-react-button@16.0.11` were served by
  the registry today. The clean releases published the next morning moved
  `latest` on, so only a pin or an old lockfile installs them.
- **The same maintainer's GitHub repositories were infected four times in
  2026**, with three more builds. Two open `global.i='5-55';` and one opens
  `global.o='5-1-55';`, each after 500 to 2,784 spaces at the end of
  `webpack.config.js`, each followed by a `_$_` string table with a different
  four-character name.

- **`itsa-cli@16.5.3` and `itsa-react-input@16.1.2`.** In the same 90-minute
  burst, and OpenSourceMalware counts them as infected, but says it could not
  read either; npm has withdrawn both and no MAL record names them. The
  2026-10-26 Socket entry lists `itsa-react-input` 16.1.2 from Socket's
  tracker, which this review cannot read. A match in this list is a confirmed
  finding, so both wait for the maintainer. They are the two most likely
  additions left.
- **The rest of Socket's hijacked releases** recorded in `bad-packages.txt`
  comments: `qrcode-vue3`, `@joyfill/*`, `@react-native-aria/separator`,
  `@testrelic/*`, `@modhamanish/rn-mm-template`,
  `@usemosaik/template-react-js`, `revine`, `spoint`, the two chatbot widgets.
  Nine of them have MAL records, read today. None of those records names a
  campaign indicator; two describe the technique
  (`@usemosaik/template-react-js`, an Ethereum dead drop in `vite.config.js`;
  `@testrelic/playwright-analytics`, a payload after 7 KB of whitespace), and
  for two (`@joyfill/*`, `spoint`) Amazon Inspector's own text says it found
  nothing. The record for `@react-native-aria/separator` 0.2.7 is the June
  2025 gluestack compromise. The link to this campaign is Socket's, read by
  the maintainer and not by this review. Moving them into
  `bad-package-versions.txt` is the maintainer's call.
- **The three XOR keys of the 2025 chain** (`$v$5;kmc$ldm*5SA`,
  `hk7#cH%v806Q/GH!`, `9KyASt+7D0mjPHFY`). Checked against the live payload:
  the first is not in the file as text, in `index.js` or `webpack.config.js`,

- **The wallet `0x9bc1355344b54dedf3e44296916ed15653844509`, the address
  `0x8eac3198dd72f3e07108c4c7cff43108ad48a71c` and four transaction hashes.**

## New techniques: maintainer decisions, not implemented

1. **The `5-` marker family is only half covered by a pattern.** The derived
   `global.i` pattern needs an A-numbered value, so `global.i='5-55'` matched
   nothing confirmed until today's fixed string. The fixed strings now cover
   `global.i='5-` and `global.o='5-` in that one spelling. A pattern over
   `global\.[io] ?= ?['"][0-9]+-` would take both quote styles and the
   spacing; it would rest on ten files in four repositories of one maintainer,
   none of them on OpenSourceMalware's lists.
2. **The `_$_` string table after the marker.** All three 2026 variants read
   today continue `;var _$_XXXX=(function(` straight after the marker, with a
   different name each time (`46e0`, `b229`, `376e`); `strong.txt` carries two
   such names as fixed strings (`_$_1e42`, `_$_fed0`). SafeDep's published hunt
   is `_\$_[0-9a-f]{4}=\(function`. On its own that is a public obfuscator's
   output, so it would be a review pattern, or a confirmed one only after
   padding.
3. **A dropper started from `package.json` scripts.** `node init &&` in front
   of `dev`, `build` or `lint`, with an extensionless `init` file beside the
   manifest (Glover; Abnormal AI saw the file). The fixed string in `weak.txt`
   gives a review line. A check would read `scripts` for `node <file> &&`
   where the file has no extension and exists beside the manifest, and read
   that file for an indicator.
4. **`.gitignore` lines removed.** The same account says the worm deleted the
   `.env` and `.vscode` lines from `.gitignore`, so that secrets and the task
   file get committed. One source, first-person. A check could only see it in
   history: a commit that removes those lines and adds `temp_auto_push.bat`.
5. **A payload after padding that carries no known string.** Before today the
   two `global.i='5-55'` files produced two review lines ("content after
   module end that looks like a payload", "line longer than 4000 characters")
   and exit 1. The next unknown marker will do the same. Whether a build
   config with a statement after several hundred blank characters should be
   more than a review is the question the gap study of 2026-11-05 asked for
   the dossier's files.
