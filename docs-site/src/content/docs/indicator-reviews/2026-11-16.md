## Upstream state

The dossier has not moved since July, and none of this week's findings comes
from it. The activity is elsewhere:

- **A third wallet.** `0x1eef0849eda15d87f64e51c73c8442cf3c8bcef3` has sent 225
  zero-value transactions since 2026-09-04, each naming a C2 address in its
  recipient bytes followed by `helloipbot!!`, the same trailer the NullReceiver
  wallet uses. Its first address, `166.88.134.75`, is already in `network.txt`
  from the `0xa322` rotation, so the wallets share servers.
- **Hijacked npm packages.** On 2026-11-03 and 2026-11-04 two publisher
  accounts of the cdmbase project released twelve versions of ten packages with
  the loader added to the entry file. Six hide it as `eval(atob("..."))` after
  131 or 157 tabs. Six use a character-swap routine and the `Function`
  constructor, with no `eval`, no base64 and no padding. There is no install
  script: the loader runs when the package is required. npm removed all twelve
  about 22 hours after the first.
- **Persistence that outlives the repository.** The second stage appends a
  snippet to npm's own `lib/cli.js`, writes a runner under `~/.node_modules/`,
  and writes a copy of the loader into the startup files of VS Code, Cursor,
  Antigravity, Discord and GitHub Desktop. Removing the package, or cleaning
  the repository, undoes none of it.
- **GitHub side.** The loaders force-pushed in late October sit after
  whitespace in a source file (`api.js`) or in a fake font named
  `fa-solid-300.ttf` or `fa-solid.lkf`. The font names have rotated again.
- **The fake-interview route.** JFrog and Abnormal AI each document take-home
  tasks that deliver the same loader.

The loader's own strings have not rotated: the request paths `/0x/cls` and
`/0x/ls`, the response header and both XOR keys are the ones already carried.

## Considered and not added

- **The ten hijacked package names** (`@adminide-stack/utils`, `cdeops`,
  `server-hemera-mongo` and seven more). Legitimate packages. The name alone
  would alarm every user of a clean version. Recorded by version, the same
  decision as the 2026-10-26 Socket entry.
- **`A10-II`, `A10-E`, `A10-%`, `A10-1234567890`**, the second variant's tags.
  Too short or too ordinary for a fixed string. They are assembled at run time
  from `'A10' + z`, so they are not in the file anyway.
- **`A10-online`, `A10-npm-handy`, `A10-new_npm`, `A10-npm_new2`** (JFrog,
  OpenSSF). Where one of these sits in a file as `global.i = 'A10-…'`, the
  `strong-patterns.txt` entry for the `global.i` tag already matches it.
  JFrog's `payload.js` opens `global.i = 'A10-online**';`.
- **`var NX = [6912847, 367, 20411, 613, 43759, 5019283]`** and the matching
  `var SX` table, which Greenflagged lists as file strings of the second
  variant. Not added because the spacing cannot be established: Greenflagged
  prints them with spaces, and the corpus case for the dossier's `var NX`
  payload writes `var NX=[6912,1]`. See New techniques.
- **`peel[ctor]`, `Forge('z'`**. Too short and too ordinary.
- **`/verify-human`**, the reporting path (Greenflagged, Abnormal AI). An
  ordinary web application can have that route.
- **`EV-CHQG3L42MMQ`, `EV-4A6OE6M0E2D`, the MD5 `9a47bb48…`, the `ss_*` command
  names.** They are in a compressed string table inside a stage that is served,
  never in a file as text.
- **The 12 tarball, 14 entry-file and 2 decoded-loader hashes, and the nine
  stage-2 hashes,** that Greenflagged publishes. No check reads those files: the entry files are
  inside `node_modules`, npm has removed the tarballs and the stages are never
  written to disk whole. The lockfile version is the usable signal. They are in
  the source if a hash check for them is ever built.
- **The Telegram fallback** (`@file_1018_bot`, bot ID `7870147428`, recipient
  `7699029999`; Abnormal AI). Read from a captured configuration, not from a
  file on disk, and bare numbers are no indicator.
- **`.orc` font files and an extensionless `init`** (Abnormal AI). No full name
  is given for the first, and `init` is far too ordinary.
- **`eslint-check`**, the task label. An ordinary label.
- **GhostAction's own indicators** (`193.32.204.199`, `#ghc2`, the workflow
  file names, the "build cache" gist). GitGuardian's working view is a
  separate operator who copied a public PolinRider launcher. This keeps the
  2026-10-19 decision. The existing `fa-solid-400.woff2` entries still flag its
  font stealer.
- **The installer names and browser-extension folder in StepSecurity's table**
  (`CameraDriverUpdate.msi`, `%USERPROFILE%\.nvm\bootstrap.cmd`,
  `extensions/job-new-alerts`, `com.accurasoft.jobalerts`). StepSecurity
  attributes them to JFrog's case record, which was not read. Second-hand, so
  not lifted. Worth reading the record next week.
- **OX Security's package list.** The page returned 403. Others report it
  counts 17 packages by adding Tailwind form look-alikes. Not read, so not
  lifted.
- **`@ethersphere/bee-js` 13.3.0.** A separate compromise that also reads an
  Ethereum contract. No source links the operators.
- **`aurum-pay`, `lwd-uri-util`, the wfx wave.** Not this campaign.

## New techniques: maintainer decisions, not implemented

1. **The loader inside an installed package is not read.** The walk prunes
   `node_modules`. A fixture with the first variant's payload line in
   `node_modules/@adminide-stack/utils/lib/index.js` exits 0; the same file
   outside `node_modules` exits 2. So for this wave the lockfile is the only
   signal, and the names are not carried because the packages are legitimate.
   This is the second and larger case for the version-aware matching the
   2026-10-26 Socket entry described: `name@version` in `bad-packages.txt`,
   read from the lockfile.
2. **Editor and app startup files.** The second stage patches VS Code and
   Cursor `out/main.js`, `node_modules/@vscode/deviceid/dist/index.js` in VS
   Code, Cursor and Antigravity, Discord's
   `modules/discord_desktop_core/index.js` and GitHub Desktop's `main.js`. A
   check would read those files at their known install paths on each platform,
   as `npm_program` reads npm's, for a confirmed indicator or a padded line.
   The markers are in `strong.txt` from today, so the data is ready.
   Greenflagged lists the macOS, Linux and Windows paths.
3. **A `var z` tag the derived pattern does not match.** The second npm variant
   opens `var z = '-II';` (also `'-%'`, `'-E'`, `'-1234567890'`), followed by
   two six-number tables `NX` and `SX`. It is in eight injected files across
   six npm releases; none is a file on OpenSourceMalware's lists. The pattern
   in `strong-patterns.txt` needs 64 or more blank characters before `var z`
   and digits after the hyphen. These files have neither: the code is inserted
   as its own lines. A pattern would have to key on `var z = '-` followed by
   the `NX` table, and whether the table is written `var NX=[` or `var NX = [`
   in the file is not established. The corpus case's `var NX=[6912,1]` suggests
   the dossier's 24 `var NX` files use the same first key, `6912847`, which the
   files from the gap study would confirm.
4. **Fake fonts that are not `.woff2`.** The font check reads `.woff` and
   `.woff2`. The October loaders use `fa-solid-300.ttf` and `fa-solid.lkf`,
   and Abnormal AI saw `.orc`. The pattern for the task command,
   `node … fa-solid-NNN.woff2`, does not match `node ./public/fonts/fa-solid-300.ttf`.
   Widening both to any extension after `fa-solid-NNN.` would cover it.
5. **A `node -i` child of a `node` process with piped standard input.** Both
   Greenflagged and Sonatype name it as the host signal for a loader that has
   run. The process check compares names only.
